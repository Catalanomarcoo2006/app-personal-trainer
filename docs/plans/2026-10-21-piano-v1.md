# App personal trainer: piano di sviluppo, Fase 1 (fondamenta) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prototipo visivo approvato da Marco, boilerplate ripulito, database Supabase con regole di accesso testate, ruoli e pannello admin funzionanti.

**Architecture:** Un'unica app Next.js 15 (App Router) sul boilerplate ZeroToShip. Supabase (progetto di sviluppo in regione UE) per auth, database e Storage; le regole di accesso stanno nel database (RLS) e sono verificate da test d'integrazione contro il progetto di sviluppo. La logica di dominio (pacchetti, incassi, attenzione) è in funzioni pure testate con Vitest.

**Tech Stack:** Next.js 15, React 19, TypeScript, Tailwind 4 + DaisyUI 5, Motion (`motion`), Remotion Player (`@remotion/player`, grafico incassi), Supabase (`@supabase/ssr`, `@supabase/supabase-js`, CLI `supabase` come devDependency), Vitest.

**Spec:** `docs/specs/2026-10-21-design.md`

## Roadmap (piani successivi, uno per fase)

La spec copre più sottosistemi: questo piano fa solo la Fase 1. Ogni fase successiva avrà il suo piano in `docs/plans/`, scritto quando la precedente è chiusa.

1. **Fase 1, fondamenta** (questo piano): prototipo, pulizia, database + RLS, ruoli, admin.
2. **Fase 2, area trainer**: Oggi, clienti, scheda cliente, libreria ~100 esercizi (seed), schede, calendario, pacchetti e incassi, impostazioni, versione telefono minima.
3. **Fase 3, area cliente**: link d'accesso, consenso, PWA, allenamento di oggi, obiettivo, misure e grafici, abitudini, documenti (Storage), richiesta di cambio.
4. **Fase 4, assistente**: sfera e pannello, API compatibile OpenAI, contesto senza dati identificativi, dolore → avviso, rete di sicurezza, confronto modelli.
5. **Fase 5, vendita e uscita**: avvisi email (Resend), account demo con dati finti, landing "Richiedi una demo", bozze legali, test end-to-end Playwright, deploy Vercel.

## Global Constraints

- Interfaccia interamente in italiano; date e mesi calcolati nel fuso `Europe/Rome`.
- Next.js 15: `await` su `headers()`, `cookies()`, `params`; server Supabase client con `await createClient()` (vedi `docs/boilerplate-regole.md`).
- Tailwind 4: configurazione solo in `app/globals.css` (`@theme`), temi DaisyUI in CSS, niente `tailwind.config.js`.
- Supabase in regione UE; RLS attiva su **ogni** tabella; chiave `SUPABASE_SERVICE_ROLE_KEY` usata solo lato server e nei test.
- Niente Stripe, niente pagamenti online, niente iscrizione libera: i trainer li crea solo l'admin.
- Stile (spec sezione 9): un solo colore forte (quello del trainer), schede morbide, numeri protagonisti; animazioni con `motion`; `prefers-reduced-motion` riduce le animazioni; suoni disattivabili.
- Slug riservati: `dashboard`, `admin`, `api`, `signin`, `privacy-policy`, `tos`, `prototipo`, `sospeso`, `_next`, `auth`.
- Mai chiavi nel repository: `.env.local` è ignorato; le chiavi le inserisce Marco.

## Review Focus

- **Slug con maiuscole, accenti, spazi o duplicati** ("Marco Rossì" → `marco-rossi`): normalizzato, i riservati rifiutati, il duplicato dà un errore chiaro → test in Task 2 e Task 7.
- **Trainer sospeso mentre i suoi clienti sono già collegati**: alla richiesta successiva il cliente non legge più nulla (RLS) e viene mandato a `/sospeso`, non solo al login → test in Task 4 e Task 6.
- **Fine mese nel fuso italiano**: un pagamento del 31 gennaio alle 23:30 ora italiana conta in gennaio, non in febbraio → test in Task 5.
- **Sedute annullate o segnate "fatta" due volte**: non scalano lezioni; il conteggio usa solo sedute `done` distinte → test in Task 5.
- **Invito admin a un'email già registrata** (per esempio un cliente): errore chiaro e nessuna riga `trainers` orfana → test in Task 7.
